# Rastercue

<!-- impeccable:product-schema 1 -->

## Platform

Windows 10/11 x64 desktop. macOS and Linux remain source/roadmap targets until separate packaged acceptance exists. The adjacent product website is a static GitHub Pages product site, not a processing service.

## Users

Graphic designers inspecting and preparing enlarged photographs, artwork, edges and text. The primary 1.0 acceptance machine is the owner's AMD RX 580 Windows work PC.

## Product Purpose

Preserve the proven Upscayl processing core while making hardware choice, model evidence, pixel output, inspection, history, recovery and failures easier to understand.

## Capabilities and Constraints

Engine binaries, arguments, model IDs, native scale detection and established processing commands are protected. The original Upscayl Vulkan route remains an explicit compatibility backend. Refreshed Vulkan and genuine native CPU paths are additive and cannot become defaults without regression and packaged hardware evidence. No backend, device, model or format silently substitutes for a failed choice.

Both sidebars remain visible at the 1366×768 compact target. Input, model and output controls form one compact flow. RGB/sRGB is the 1.0 colour boundary. Existing preferences, history and source files remain intact. Compute selection has no vendor whitelist: only the bundled engine probe decides whether a detected Vulkan device is available.

## Brand Commitments

Rastercue uses its geometric R-and-pixel identity, periwinkle #A5A0FF, graphite #14161B, slate #22252D and soft white #F1F2F6. Upscayl attribution and complete component/model/font notices remain visible. No analytics, cloud image upload or automatic diagnostic transmission. Updates come only from the eventual YazeKT/Rastercue GitHub Releases repository.

## Product Principles

- Preserve working processing behaviour and user files.
- Maximise preview space without hiding sidebars.
- Explain settings and model limits honestly.
- Keep history lightweight; create exact-byte `.rastercue` archives only on explicit request.
- Verify packaged behaviour; configuration alone is not proof of platform support.
- Keep public claims inside recorded evidence: AMD Vulkan is owner-tested; other devices remain engine-probe based; CPU claims require the final packaged backend run.

## Evidence on Hand

Owner acceptance on 24 September 2026 covers the Windows 10/11 x64 workflow and AMD RX 580 Vulkan path. Protected hashes, packaged processing checks, source tests, archive/restore tests and product-site validation are recorded. Intel, NVIDIA and other Vulkan devices remain engine-probe based rather than universally certified. The native CPU backend passed its no-Vulkan probe, format/model matrix and packaged UI job. No confirmed trademark clearance or Windows/macOS signing credentials exist.
